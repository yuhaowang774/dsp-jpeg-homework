# JPEG压缩原理与实现——分块DCT、量化及率失真分析

这是DSP大作业的第一轮可运行原型。核心算法自行编写，所有MATLAB文件均有中文函数说明和关键步骤注释；没有直接移植网上编解码项目。

## 一键运行

在本机 **MATLAB R2024b** 中把当前文件夹切换到本目录，然后执行：

```matlab
% 执行自测、载入1024彩色输入、70组实验、绘图和实验纪要生成。
result = run_project;
```

程序仅使用基础MATLAB。不要求Image Processing Toolbox、Signal Processing Toolbox或Communications Toolbox。`data/demo_photo_1024_page.png` 必须保留：它是网页演示台无损导出的同一份像素，缺少时程序直接报错而不是换图凑数。不需要联网。

单独处理自己的彩色PNG：

```matlab
% 核心输入必须是 H×W×3 的 uint8；输出是真正的基线JPEG，而非改后缀的MAT文件。
addpath('src');
image = imread('data/demo_photo_1024_page.png');
info = jpeg_encode_color(image,'my_result.jpg',50,'420');
[reconstructed,details] = jpeg_decode_color('my_result.jpg');
% 独立检查标准解码器是否能读取，不参与自编编解码流程。
independent = imread('my_result.jpg');
```

只运行测试：

```matlab
% 测试非8倍数尺寸、极端亮度、随机纹理、ZRL、FF填充、三种采样和错误文件等。
addpath('src','tests');
tests = run_tests;
```

- 默认分析块由 `chooseDefaultBlock()` 在整幅图上挑选（步长 2 个块、避开四周 2 个块）：先要求交流能量不为零且 55% 以上落在 `u+v ≤ 4` 的低中频，再按 `√(低中频能量) × 相干度^1.5 × 曝光 × (1 − 0.4·中心距离) × 色度增益` 打分，其中色度增益 = `0.15 + 0.85·min(1, σ(Cb,Cr)/12)`，σ 为块内 Cb/Cr 的联合标准差。最终还要求这块**亮度适中（均值 80–182）**且**色度起伏 ≥ 8**，这样 YCbCr 那一步的 Cb/Cr 面板能看出颜色变化、减 128 后两侧都有值；灰度图或单色图达不到色度条件时自动退回纯结构打分。目的：纯噪声块量化后整片归零、纯天空块几乎没有交流系数、灰调块的色度面板又一整片纯洋红/纯青，都不适合讲解。默认风景图（1024）落在 `(82,86)`：Y 19–131、Cb 81–128、Cr 130–158，QF=50 时量化置零 48/64。点击图像后即改为手动选区。

- 「Huffman」节点（07.3）：上方固定三列**标准原文截图**——ITU-T T.81 附录 K 的 Table K.3（亮度 DC 全表）、Table K.5 sheet 1 上半（0/0–1/7）与下半（1/8–3/A），取自 W3C 公开镜像 `itu-t81.pdf`，裁成 `web/assets/t81_table_k3_dc.png`、`t81_k5_top.png`、`t81_k5_bottom.png`；表图按列宽放大到 400–640px 高，三张图下方不显示图注与「原版整页」链接，列宽仍装不下的小字，点任意一张表图即可在原图尺寸的覆盖层里看清楚（Esc 或点空白处关闭）。下方直接是本块位流，一格一个符号，格内竖排「符号名 / Huffman 码（蓝）/ 幅值位（黄）」，幅值位右侧用 `= 数值` 标出它还原出的真实系数（`011 = -4`），读者不必自己按补码换算；再下面是唯一码字清单与统计。位流下面还加了一条「编码后的数据」：把本块 17 个符号首尾相接，拼成真正写进码流的那串 0/1（蓝 = 码字、黄底 = 幅值位），虚线按整幅码流的**真实字节边界**插入——起点取该块的 `bitStart`，因此首段常常不满 8 位，正好说明「块与块之间不补位」；末行给出整幅总位数、末尾补的几个 1 与熵编码字节数。页面上的标准表标题、位流标题与「码字部分省百分之多少」的收益读数都已删除。本页不画码树，也没有表下说明与“正在写 / 已完成字节”状态行；点「逐符号写入位流」时位流按符号逐段增长，读数只保留已写入位数与进度。
- 码树由码长表按「码长递增、同长按符号值递增」唯一生成：从根读到叶的 0/1 就是码字，越常用的符号离根越近，短码落在高频符号上。**码长表由 T.81 附录 K 标准给定，不为当前图像现场统计符号频率**（标准制定时已按大量自然图像统计好），编解码双方共用同一张表，因此无需在码流中传树。页面上的「8 个唯一码字 / 17 个符号」只用于展示本块用了多少种符号、省了多少位，不参与码字生成；这一点同时写进了课件导语、原理、公式与观察要点。
- 「DC 差分与 AC 游程」节点按「问题 → 直觉 → 规则 → 收益」重写叙述（导语放在左侧说明面板，演示台里不再摆三句话卡片）。主体是一张双轨图：上排 64 个 Zigzag 系数（每格直接写数值，浅灰格里的 0 连成一片），下排每个格子是一个符号，格内自上而下写「符号 / 该符号的数值」，图右上与图注点明 AC 的 (run, size) 构型：run = 前面跳过几个 0，size = 幅值占几位；橙色折线把当前符号与它覆盖的系数区间连起来。双轨图按 1240×300 的逻辑尺寸绘制再由容器放大，格内数值与符号的字号用 `measureText` 逐格校验，三位系数也不会压到邻格。图下新增「符号怎么读」解剖卡，把本块前 4 个符号逐个拆成 run / size / 幅值位（DC 与 ZRL / EOB 各有自己的读法）。本页不列符号明细表（码字、幅值位与合计位数统一放在下一步「Huffman」的位流格与码字清单里），逐拍动画只点亮下排符号并同步读数。
- 主界面不画滚动条：`.main`、`.scroll`、`.bits`、`.stepper` 都设了 `scrollbar-width:none` 与 `::-webkit-scrollbar{width:0}`，内容超出时仍可用滚轮/触摸/键盘滚动；切换节点时底部步骤条会把选中按钮滚到中间，窄屏上也能看到当前在第几页。
- 动画覆盖：分块巡览（行优先、逐行从左到右扫描）、DCT 余弦波逐项叠加（一维分解）、DCT 行列两阶段分解、逐系数量化、Zigzag 扫描、RLE 游程条带、Huffman 逐符号写入与字节分组、熵编码按 MCU 拼接、熵解码位游标、IDCT 基函数累加，以及步骤切换淡入。
- 所有动画由页面内 `ANIM` 配置统一定义触发条件、持续时长和缓动曲线；离散流程使用 `steps` 节奏，连续流程使用标准三次或正弦缓动。步骤切换和设置抽屉共享统一过渡变量。
- 性能与适配：移动端降低设备像素比上限、动画节拍按屏幕与性能档位缩放；块巡览只重绘高亮层，位流写入/解码/拼接按状态变化更新；系统开启“减少动态效果”时自动压缩所有动画时长。
- 底部只保留步骤条；多数动画由步骤内的工具按钮触发，DCT 行列分解、DCT 逐项重建与 Zigzag 扫描则是进页即自动循环播放，点对应按钮可暂停/继续（Zigzag 继续时从当前格接着扫）；开启“减少动态效果”时这些页停在完成态。
- 页面中的熵解码直接读取编码产生的位流，逐块验证编码/解码符号一致；PSNR 在重建步骤的参数区显示。
- `08.1 熵解码` 与 07.x 用同一套版式，四块统一 1360px 居中：① 顶部指标卡（位范围 / 本块位数 / 符号数（编码→解码）/ 一致性）；② 逐符号对照表（`#` / 编码符号+码字 / 幅值位 / 解码符号+码字 / 还原值，幅值位沿用 07.3 位流格的黄色标记，播放时当前行高亮、已解行变灰，行高压到 28px 以便一屏看完）；③ **本块位流的分段图**——一段一个符号、宽度正比于该符号占的位数，DC 蓝、AC 橙、EOB/ZRL 深灰，悬停可见序号与位数；④ 「位流片段」卡片带图例（已解码位 / 读游标 / 上下文）。四块自上而下就是解码顺序，窄屏用 `max-height` 收口并在读数里给出符号总数；`compact` 模式下表格单独放宽到 40vh，不被通用的 200px 压扁。
- 快捷键：`←/→` 切换步骤，`↑/↓` 调整 QF，`Z` Zigzag 扫描，`B` 一维余弦叠加。

## 已实现范围

## 实验设计

- 输入：`data/demo_photo_1024_page.png`，1024×1024 RGB，与网页演示台同一份像素。
- QF：5、10、20、35、50、65、80、90、95、100。
- 方法：自编频率加权（T.81 K.1/K.2）、自编等步长（三分量共用一个标量步长）、MATLAB `imwrite` 基线。
- 矩阵：3 采样 × 2 自编方法 × 10 QF = 60 组；`imwrite` 不暴露采样因子，实测只有一条曲线（从 SOF0 解析为 4:2:0）× 10 = 10 组；共 70 组、70 个真实 jpg。
- 实测：完整字节数、bpp、压缩比、MSE、PSNR、Y-PSNR、MAE、零系数比例、熵位数、读写耗时等。
- 等码率：按采样分别在加权与等步长曲线共同覆盖范围内线性插值，明确标记为估计，不外推、不冒充实测。
- 不默认“加权一定更好”，不把同 QF 比较当成等码率比较。

## 彩色实验与网页对照

- 输入：`data/demo_photo_1024_page.png`，由 `tools/export_page_photo.py` 从 `web/photos.js` 原样导出（无损 PNG）。**不要用 `data/demo_photo_1024.jpg`**：它是另一条解码路径，与页面像素每通道平均差 1.54、最大 23，量化系数会对不上。脚本末行会与 `data/page_pixels.json` 的通道和校验，不一致直接报错。
- 编码/解码：`src/jpeg_encode_color.m`、`src/jpeg_decode_color.m`（读文件用 `src/jpeg_read_scan_color.m`）。DCT/IDCT 采用 `src/jpeg_dct_web.m`、`src/jpeg_idct_web.m`，与前端**同累加顺序**——用矩阵乘会在 `.5` 取整边界上翻转，实测有 125/3,145,728 个系数不同。
- 取整规则：两端都必须使用「四舍五入、远离零」。前端不能写 `Math.floor(v + 0.5)`：当 `v = 0.49999999999999994` 时 `v + 0.5` 会被舍入成 `1.0`，把严格小于 0.5 的量进位；修复前 30 档中有 20 余档各差 1–3 个系数。`web/jpeg_codec.js` 的 `matlabRound` 已改为「先取 floor/ceil 再比较余量」，并由 `tests/web/test_codec.js` 固定该行为。
- 规模：自编 60 组 + `imwrite` 10 组 = 70 个文件，输出 `results/measurements.csv`；其中自编频率加权的 30 组另存 `results/color_reference.json`，仅供 `web/color_reference.js` 与前端逐位断言。
- 口径：原始字节 = 宽×高×3；PSNR 为 RGB 三通道全图。**MATLAB 实测（measurements.csv、纪要、`10.1–10.4` 页）**的压缩比 = 原始字节 / **完整文件字节**（含 609 字节头与 FF00 填充）。**网页演示页（07.4 熵编码输出、08.4 重建页及其 MATLAB 对照表）**的压缩比 = 原始字节 / **熵编码字节**（含末尾补位，不含表、标记与 FF00 填充），只看 DCT+量化+熵编码本身压掉了多少；对照表里的 MATLAB 一栏也按 `(entropyBits+paddingBits)/8` 换成同一口径。两种口径在页面上都标明了分母，文件字节、熵位等原始量两端逐位相同，可直接相减。
- 网页数据：`src/export_color_reference.m` 把 JSON 转成 `web/color_reference.js`，最后一页据此渲染对照表；`tests/web/test_color_reference.js` 断言两端熵位、分量位、文件字节、零系数占比完全相等，PSNR 差 < 1e-6 dB。
- 交叉验证：MATLAB 侧 `imread` 能解出同样尺寸的图像，本轮 60 组自编最大像素差 4（libjpeg 的整数 IDCT 与色度上采样与本项目不同，因此只做有界校验，不要求逐像素相同）；自编编码→自编解码的量化系数完全互逆。

## 答辩时必须说清楚

- DCT本身不丢信息，量化才是主要有损步骤，熵编码无损。
- 压缩比基准为原始像素字节数（宽×高×3，1 字节/通道），不是输入 PNG 大小。MATLAB 实测的分母是完整 `.jpg` 文件字节；网页 07.4 / 08.4 的分母是熵编码字节（不含 609 字节文件头）。答辩时先说清用的是哪一个。
- 实际文件大小包含表、标记、填充；极小图可能不压反涨。
- Q不是“画质百分比”；Q=100不保证逐像素无损。
- 图像内容影响压缩表现；PSNR不等价于人类观感。
- MATLAB 实验和网页演示都只用了一张 1024×1024 自然照片，属于可行性验证，不可夸大为普遍结论。
- 组员分工、姓名及成绩权重待你们实际协商后填写，程序不虚构这些信息。
